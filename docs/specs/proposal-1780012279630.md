# Proposal: 多平台支持

## Problem Statement

Nova 当前仅支持 Claude Code 作为唯一的 AI 平台。虽然代码中已预留 `PlatformClient` 抽象基类和 `EnvironmentAdapter` 接口，但实际只实现了 `ClaudeCodeClient` 和 `ClaudeCodeAdapter`。Codex、OpenClaw、Hermes Agent 有占位入口但直接报错，OpenCode 完全未提及。

这限制了 Nova 的适用范围——使用其他 AI 编码工具的团队无法接入 Nova 的工作流编排能力。

## Proposed Solution

并行实现四个平台的完整适配，每个适配包含三层：

1. **PlatformClient 子类** — 封装各平台 CLI 的 spawn 方式、参数传递、输出解析
2. **EnvironmentAdapter 实现** — 生成平台特定的 skill/command 文件
3. **平台检测** — `nova init` 时自动检测环境，`resolvePlatformClient` 正确路由

### 目标平台

| 平台 | CLI 命令 | skill 格式 | 配置检测 |
|------|---------|-----------|---------|
| Claude Code | `claude --print` | `.claude/commands/*.md` | 已实现 |
| OpenAI Codex | `codex` | 待调研 | `codex` CLI 存在性 |
| OpenClaw | `openclaw` | 待调研 | `openclaw` CLI 存在性 |
| Hermes Agent | `hermes-agent` | 待调研 | `hermes-agent` CLI 存在性 |
| OpenCode | `opencode` | 待调研 | `opencode` CLI 存在性 |

### 架构变更

```
src/cli-core/
├── platform-client.ts          # 扩展：新增 4 个 Client 子类
├── adapters/
│   ├── claude-code.ts          # 已有
│   ├── codex.ts                # 新增
│   ├── openclaw.ts             # 新增
│   ├── hermes-agent.ts         # 新增
│   └── opencode.ts             # 新增
└── init-manager.ts             # 修改：平台自动检测逻辑
```

## User Stories

1. **作为 Codex 用户**，我希望 `nova init` 能自动检测 Codex 环境并生成对应的 skill 文件，这样我可以在 Codex 中使用 Nova 工作流
2. **作为 OpenClaw 用户**，我希望 `/nova-implement` 能通过 OpenClaw CLI 执行任务，这样我不需要切换到 Claude Code
3. **作为多平台团队**，我希望同一项目能配置不同成员使用不同 AI 平台，这样团队不受单一工具限制
4. **作为 Nova 维护者**，我希望新增平台只需实现两个接口，这样扩展成本可控

## Scope & Deliverables

### In Scope

- `CodexClient` + `CodexAdapter` 完整实现
- `OpenClawClient` + `OpenClawAdapter` 完整实现
- `HermesAgentClient` + `HermesAgentAdapter` 完整实现
- `OpenCodeClient` + `OpenCodeAdapter` 完整实现
- `resolvePlatformClient` 路由逻辑更新（移除 "not yet supported" 报错）
- `nova init` 平台自动检测（检测已安装的 CLI 工具）
- 每个平台的 CLI 参数调研和 skill 文件格式调研
- 单元测试覆盖所有新 Client 和 Adapter

### Out of Scope

- 平台间迁移工具（从 Claude Code 迁移到 Codex）
- 平台能力对齐（不保证所有平台功能完全等价）
- Web UI 或图形界面
- 平台特定的性能优化

## Success Criteria

1. `resolvePlatformClient('codex')` 返回可用的 `CodexClient`，不再报错
2. `nova init` 在检测到 Codex/OpenClaw/Hermes Agent/OpenCode CLI 时自动生成对应 skill 文件
3. 每个新平台的 `sendPrompt` 能正确调用对应 CLI 并解析输出
4. 现有 Claude Code 功能无回归（所有现有测试通过）
5. 新增平台的单元测试覆盖率 ≥ 80%

## Risks & Constraints

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 各平台 CLI 接口不稳定 | 适配器需频繁更新 | 抽象层隔离变化，CLI 参数可配置 |
| 部分平台 skill 文件格式未知 | Adapter 实现可能不准确 | 先调研再实现，标注已知限制 |
| 平台能力差异大（如无 --print 模式） | 某些 Nova 功能可能不可用 | 降级处理 + 明确文档说明 |
| 测试环境有限 | 无法在 CI 中测试所有平台 | Mock CLI 响应 + 集成测试标注 manual |

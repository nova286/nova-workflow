# Nova — AI Workflow Orchestration Framework

Nova is a CLI tool that orchestrates AI-assisted software development through a structured five-phase workflow: propose → design → implement → verify → archive. It works with any Claude Code setup, and optionally integrates three AI methodologies (OpenSpec, Superpowers, ECC) for enhanced capabilities.

> **THE AI Workflow is All You Need**

## Setup

```bash
npm install
npm run build
npm install -g .
```

## Commands

### Skill Commands (run inside Claude Code session)

| Skill | Purpose |
|---|---|
| `/nova-propose` | AI generates proposal.md — orchestrates brainstorming |
| `/nova-design` | AI generates design.md + YAML task list — orchestrates brainstorming + writing-plans |
| `/nova-implement` | Execute tasks via task-type routing with retry & tracing |
| `/nova-verify` | Run code review + security review via ECC skills |
| `/nova-iterate` | Roll back to a previous phase for iteration |

### CLI Commands (run in terminal)

| Command | Purpose |
|---------|---------|
| `nova init` | Initialize Nova in a project |
| `nova archive` | Merge artifacts and clean up |
| `nova status` | Display phase progress and task completion |
| `nova context --task-id <id>` | Print TaskContext JSON for a task |
| `nova guard <from> <to>` | Check if a phase transition is valid |

## Key Patterns

- **Skill-based execution** — AI phases run as Claude Code slash commands (`/nova-design`, etc.) inside the session, zero startup cost
- **State file** `.nova.yaml` — single YAML file with atomic writes (write tmp → rename), mutex-guarded
- **Phase guards** — every transition is gated (e.g., open→design requires proposal done); rollback transitions always allowed
- **Task routing** — `/nova-implement` routes tasks by type: implementation (direct), testing (TDD skill)
- **Skill orchestration** — Nova skills call real skills (brainstorming, writing-plans, TDD, code-review, security-review) instead of generating content from thin templates
- **Iteration support** — `/nova-iterate` rolls back to earlier phases, preserving code files

## Dependencies

- **Runtime**: commander, inquirer, ora, chalk, yaml, async-mutex
- **Dev**: typescript, ts-jest, jest, @types/*
- **External**: Claude Code — all AI phases run as skills inside the session

## Notes

- `inquirer` v9, `ora`, `chalk` are pure ESM — Jest uses `moduleNameMapper` to stub them
- Phase keys in `.nova.yaml` (`open`, `build`) differ from user-facing names (`propose`, `implement`) — mapped in status.ts
- 6 skill files generated by `nova init`, 5 operational CLI commands
